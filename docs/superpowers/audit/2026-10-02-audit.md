# Audit A: hyperpress-utils, hyperpress-season, hyperpress-program, hyperpress-robot

Scope: all git-tracked PHP in the four plugins (24 files: 9 utils, 9 season, 4 program, 2 robot). No `templates/` directory exists. Read-only review; no code run. ## Findings

### U1 - medium - Season/post-type rewrite rules are added only in memory and are not persisted when a plugin is activated
`hyperpress-season/src/Rewrite.php:10,24-28`; `hyperpress-robot/src/Plugin.php:29-33`
```php
add_action( 'init', array( self::class, 'add_rules' ), 20 );
...
add_rewrite_rule( '^' . preg_quote( $season_slug ) . '/([^/]+)/' . preg_quote( $type->has_archive ) . '/?$', ...
```
Impact: `add_rules()` loops over post types that are registered by `init` priority 20. In Robot's activation request, Season's rules were added at `init` before Robot's CPT existed, so `Robot::activate()` registers the type and calls `flush_rewrite_rules()`, but the `seasons/{slug}/robots/` rule is not in `extra_rules_top` and is not persisted. Season has no activation hook either, so a fresh install also never flushes. Result: `/seasons/2026/robots/` returns 404 until someone re-saves Permalinks. The same applies to every plugin whose `hyper_*` CPT has an archive and is activated after Season. Public-facing, no data exposure.
Fix: in each CPT plugin's `activate()`, call `Rewrite::add_rules()` after `register()` and before `flush_rewrite_rules()`, or hook a flush on a version option change in Season (`Rewrite::add_rules()` then flush when the set of archive types changes). Season should also flush on its own activation.
Test: integration test. Register Season and a CPT with `has_archive`, simulate activation (register, `Rewrite::add_rules()`, `flush_rewrite_rules()`), then assert `get_option('rewrite_rules')` has a key matching `seasons/([^/]+)/robots/?$`. Before the fix the key is absent.

### U2 - low - Customizer settings with `'sanitize_callback' => ''` for the post-type lists
`hyperpress-season/src/Customizer.php:36-43` (line 41); `hyperpress-program/src/Customizer.php:15-22` (line 20)
```php
'type'              => 'theme_mod',
'default'           => array( 'post' ),
'sanitize_callback' => '',
```
Impact: an empty callback means no sanitizing filter. A crafted Customizer save (admin only, `edit_theme_options`) can store any scalar/array in `hyperpress_season_post_types` / `hyperpress_program_post_types`. `TaxonomyRegistrar::resolve_object_types` (`hyperpress-utils/src/TaxonomyRegistrar.php:53-55`) keeps only non-empty strings, so the worst case is the taxonomy being attached to non-existent or non-public types (for example `attachment` or `nav_menu_item`). No injection path.
Fix: `'sanitize_callback' => array( self::class, 'sanitize_post_types' )`, which casts to array and keeps `array_intersect( $value, array_keys( get_post_types( array( 'public' => true ) ) ) )`.
Test: unit test on the sanitizer with `['post','nope','<script>']` returning `['post']`, and a non-array returning `[]`.
- **FIXED**: both post type settings now use PostTypeDropdownControl::sanitize_post_types, which keeps only registered public post type keys and turns non-array input into an empty array (tests/integration/SeasonProgramCustomizerTest.php).

### U6 - low - `selected()` compares an array value to a string, giving PHP warnings and no preselect - **FIXED**
`hyperpress-utils/src/Controls/PostTypeDropdownControl.php:52`
```php
selected( $this->value(), $post_type->name, false ),
```
Impact: confirms plan row 6, part 2. The setting value is an array (`default => array('post')`). WordPress's selected helper casts both sides to string, so an array value raises "Array to string conversion" (E_WARNING in PHP 8) once per option on every Customizer load, and no option is ever marked selected server-side. The Customizer JS re-syncs the selection, so users rarely see wrong behaviour, but logs fill up and `display_errors` leaks file paths in dev. Admin-only, Customizer-only. (This is from knowledge of core's helper; the core file was not opened this session, so verify by the test below.)
Fix: `$value = (array) $this->value();` and use `in_array( $post_type->name, $value, true ) ? 'selected' : ''` (escape with `selected( true, in_array(...), false )`).
Test: render with value `['post']` under `error_reporting(E_ALL)` with a warning-to-exception handler and assert no warning and that `value="post"` has `selected`.
**FIXED**: the multi-select now preselects via `in_array( $post_type->name, (array) $this->value(), true )`, with no array-to-string warning.

### U8 - low - `preg_quote()` without the `#` delimiter in the rewrite rule
`hyperpress-season/src/Rewrite.php:25`
```php
'^' . preg_quote( $season_slug ) . '/([^/]+)/' . preg_quote( $type->has_archive ) . '/?$', // phpcs:ignore WordPress.PHP.PregQuoteDelimiter.Missing -- plugins audit
```
