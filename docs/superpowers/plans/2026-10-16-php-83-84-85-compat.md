# PHP 8.3 / 8.4 / 8.5 Compatibility Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the plugins and the Foundation theme install and pass their suites identically on PHP 8.3, 8.4 and 8.5, so the owner can move production (RunCloud offers all three) without surprises.

**Architecture:** A cross-version run of the suites (2026-10-16, throwaway php:8.3/8.4/8.5 images) found four things: the committed `composer.lock` files were resolved on 8.5 and cannot install on 8.3; two unit suites assert PHP 8.5 specifically; `DateDistance` behaves differently for an invalid `locale` on 8.3; and two tests call `setAccessible()`, which is deprecated on 8.5. Each gets a small fix, verified on all three versions with throwaway images.

**Tech Stack:** PHP 8.3 / 8.4 / 8.5 (official `php:*-cli` images), Composer 2, PHPUnit 9.6, WordPress test suite, MariaDB 11.4, Docker.

**Spec:** none (maintenance follow-up to `docs/superpowers/plans/2026-10-16-uikit-stages-5-7-plugin-lint-package.md`, "Owner decisions" and the verdict's PHP question). The evidence is the matrix run summarised in the Context below.

## Context (findings being fixed)

- `composer install` from the committed locks of `plugins/` and `themes/hyperpress-foundation/` fails on PHP 8.3: `doctrine/instantiator 2.1.0 requires php ^8.4` (a dev dependency pulled in by PHPUnit 9.6). With `config.platform.php = 8.3.0` and an update, only `doctrine/instantiator` changes (2.1.0 to 2.0.0). `themes/hyperpress-uikit` already has this pin.
- `plugins/tests/unit/SmokeTest.php` and `themes/hyperpress-foundation/tests/unit/SmokeTest.php` assert `PHP_VERSION_ID >= 80500` (`test_runs_on_php_85`), failing on 8.3 and 8.4 by design.
- `plugins/tests/integration/Shortcodes/DateDistanceInvalidTest.php` (`test_an_invalid_locale_falls_back_to_the_plain_number`) fails on 8.3 only: `new \NumberFormatter('\\\\', ORDINAL)` throws `ValueError` on 8.4+ (caught in `plugins/hyperpress-shortcode/src/Shortcodes/DateDistance.php:55`, falling back to the plain number) but silently builds a default-locale formatter on 8.3 (`'10th'`).
- `setAccessible()` (a no-op since PHP 8.1, deprecated in 8.5) is called at `plugins/tests/integration/SocialIconsTest.php:193` and `plugins/tests/integration/Media/AvifViaGdTest.php:183` and `:228`.

## Global Constraints

- The PHP floor stays `>=8.3` everywhere (`composer.json` `require.php`, plugin headers `Requires PHP 8.3`, PHPCS `testVersion`). Nothing here raises it.
- PHP and Composer run in Docker only. Documented way for the plugins and Foundation tooling: from `plugins/` or `themes/hyperpress-foundation/`, `docker compose run --rm php composer <script>` (never composer on the host). `plugins/vendor` and `themes/hyperpress-foundation/vendor` are already root-owned from earlier runs; do not "fix" that here.
- Cross-version verification uses throwaway images built from copies of the existing Dockerfiles with only the base tag changed (`php:8.3-cli`, `php:8.4-cli`, `php:8.5-cli`), named `hpmx-php83|84|85`, a private network and a throwaway `mariadb:11.4`; all containers, networks and images are removed at the end (Task 4). Scratch work lives under `/tmp/opencode/phpmatrix/`, never in the repo. Do not touch the running compose projects `hyperuikit`, `hyperalumni`, `hyperonline`, `hyperpress-plugins`, `hyperpress-theme`.
- Never read or print real `.env*` files; shell commands containing the string `.env` are rejected.
- Commit style: follow `git log` (`type(scope): lowercase summary`, e.g. `fix(season): …`, `build: …`, `docs: …`); explicit pathspecs written out (`git add <paths>` then `git commit -m "..." -- <paths>`); never a bare `git commit`, never `git add -A`. Nothing is pushed. Work is on branch `fix/php-83-84-85-compat`, cut from `master`.
- Shell setup for node/pnpm commands: `source ~/.nvm/nvm.sh && nvm use && export PATH="$HOME/.local/share/pnpm/bin:$PATH"` (no pipe after `nvm use`). Files touched must stay Oxfmt-clean (`pnpm fmt:check`).
- Baselines on 8.5 (must still hold after every task): plugins unit 176 tests / 481 assertions, plugins integration 1128 tests / 3348 assertions / 6 skipped, plugins PHPCS 143 files, Foundation unit 41 / 83, Foundation integration 312 / 862 / 12 skipped, uikit theme unit 18 / 32.

## Review Focus

- Lock changes limited to `doctrine/instantiator` plus the `platform-overrides` and `content-hash` lines; no other package version moves.
- The `DateDistance` change must not alter output for valid locales (`en-US`, `en_US`, `nb-NO`, `de-DE`) on any version, nor for `locale=""` (explicit empty) compared with today.
- Removing `setAccessible()` is safe on 8.3 (Reflection members are accessible by default since 8.1).
- The relaxed smoke guard still fails on a PHP older than the floor.
- The throwaway harness leaves no containers, networks, images or root-owned files behind.

### Task 3: Make an invalid `locale` behave the same on every PHP version (TDD)

**Files:**

- Modify: `plugins/hyperpress-shortcode/src/Shortcodes/DateDistance.php`, `plugins/tests/integration/Shortcodes/DateDistanceInvalidTest.php`

**Interfaces:**

- Produces: `DateDistance::is_valid_locale( string $locale ): bool` (private static; true when the already underscore-normalised locale matches the BCP 47 shape `^[a-z]{2,3}(-[a-z0-9]{2,8})*$`, case-insensitive). `render()` skips the ordinal formatter and returns the plain number when `suffix` is requested with a locale that fails the check, identically on 8.3, 8.4 and 8.5; an explicit empty `locale=""` keeps today's behavior (default-locale ordinal), because `shortcode_atts` passes the empty string through.

- [x] **Step 1: Write failing tests** (in `DateDistanceInvalidTest`; each builds the date as the existing tests do): `'\\\\'` and `'!!'` and `'en US'` (space) return the plain `'10'`; `'en-US'` and `'en_US'` return `'10th'`; `'de-DE'` returns the same string as `new NumberFormatter('de-DE', ORDINAL)` produces for 10 (assert equality with that computed value, not a literal); explicit `locale=""` returns the same as the default-locale formatter (computed). Run on **PHP 8.3** with the harness: the invalid-locale tests FAIL there (capture the output).
- [x] **Step 2: Implement** `is_valid_locale()` and the guard in `render()` before constructing the `NumberFormatter` (keep the existing `try/catch`).
- [x] **Step 3: Verify (GREEN) on all three versions:** the shortcode tests pass on 8.3, 8.4 and 8.5; the full plugins integration suite passes on all three with the baseline counts (1128 tests / 6 skipped, plus the new tests); `composer lint` in `plugins/` (PHPCS) passes; `pnpm fmt:check` passes.
- [x] **Step 4: Commit** `fix(shortcode): validate the date-distance locale so 8.3 and 8.4+ agree` over the two files.
