# AGENTS.md

Companion WordPress plugins for the hyperPress theme (PHP; only `hyperpress-example` has a small Node build step). Each `hyperpress-*/` dir is an independent plugin. There is a root `composer.json`, a Docker test toolchain, phpcs and PHPUnit. There is no CI.

Part of the hyperPress monorepo (`plugins/`); the root `../AGENTS.md` also applies.

## Plans and specs

- Work is driven by `../docs/superpowers/` (`specs/`, `plans/`, `audit/`). Read the relevant plan and spec before starting work.
- Tooling: PHP runs in Docker only. Run everything through `docker compose run --rm php <cmd>` from this dir (never composer on the host): `composer lint`, `composer test:unit`, `composer test:integration`.
- PHP versions: the suites run and pass on PHP 8.3, 8.4 and 8.5, and `composer.lock` is pinned with `config.platform.php = 8.3.0` so it installs on 8.3. To repeat: build throwaway `php:8.3-cli` and `php:8.4-cli` images from `plugins/Dockerfile` with only the base tag changed, run the suites in them against a throwaway MariaDB 11.4, then remove the images and containers.
- There are 18 plugin directories: 17 plugins, including `hyperpress-shortcode` and `hyperpress-media`, which were extracted from the theme, plus the `hyperpress-example` stub (it consumes the shared Sass lib and is not part of the plugin conventions below).
- Packaging: `bin/package [plugin ...]` runs on the host (needs git and unzip). It writes `packaged/<plugin>-<version>.zip` from committed files only; with no args it packages every `hyperpress-*/` directory, including `hyperpress-example`, whose git-ignored `dist/uikit.css` is then missing from its zip, so name the plugins you want. `<version>` is the nearest ancestor version tag of HEAD (`2027.1.0` or `v2027.1.0`; leading `v` dropped, no commit suffix; other tags are ignored), written into the `Version:` header of the zipped main file only (sources are untouched). With no version tag it warns on stderr and uses each plugin's committed header version. Tag the release commit before packaging.

## Plugin conventions

- Layout: `hyperpress-<name>/hyperpress-<name>.php` (header, ABSPATH guard, PSR-4 autoloader, hook `Plugin::boot` on `plugins_loaded`) plus `src/` (namespace `HyperPress\<Name>`, one class per concern). Registered keys are `hyper_*`; other identifiers are `hyperpress_{plugin}_{field}`. Text domain `hyperpress`.
- Every header carries Version `2026.0.0` (a dev/fallback value only: `bin/package` stamps the nearest version tag into the packaged copy), Requires at least `6.9` and Requires PHP `8.3`; `Requires Plugins` follows the table in `../docs/superpowers/specs/2026-10-02-plugins-convention-and-shared-code-design.md`.
- `hyperpress-utils` is the base dependency, and `hyperpress-season` is a base CPT/taxonomy that many plugins depend on. Meta boxes come from the `meta-box-aio` plugin.
- The top-level "hyperPress" wp-admin menu lives in `hyperpress-utils` (`AdminMenu`); other plugins attach their settings pages to it with `parent => AdminMenu::SLUG`.
- `hyperpress-student` is a single-file placeholder with no behavior.
- Admin list filters: taxonomy "All …" dropdowns come from `HyperPress\Utils\TaxonomyAdminFilter::register( $taxonomy, static fn() => __( 'All …', 'hyperpress' ) )`, called from the plugin's `Plugin::register()` (on `init`). A dropdown shows only on post types attached to the taxonomy and only when it has terms. Core filters through the taxonomy's `query_var`; a non-public taxonomy has one only inside wp-admin (WordPress forces it off elsewhere).
- Front page countdown: the theme prints whatever `hyperpress_frontpage_countdown_html` returns, and `hyperpress-frontpage` (`Countdowns`) answers it with exactly one countdown chosen from candidates that plugins append through the `hyperpress_frontpage_countdown_candidates` filter. A candidate is an array: `id` (string, unique), `start` (`DateTimeImmutable`, the instant it counts to), `show_from` / `show_until` (`?DateTimeImmutable`, the window is open when `show_from < now < show_until`, both strict), optional `fallback_after` (`?DateTimeImmutable`, a soft end: past it the candidate is used only when nothing else is open), `priority` (int, default 10) and `render` (callable returning the HTML, called only for the winner). The open candidate with the earliest `start` wins (then priority, then id); if only fallbacks are open, the latest `start` wins. Sources today: the countdowns chosen on the Front Page settings page (hide-before/after from `hyperpress-countdown`'s `Window`; no Hide After means a soft end at the end of the event's day) and competitions (`hyperpress-competition`'s `FrontpageCountdown`, from a lead time before the first counted day until the last counted day ends). `Countdowns::html()` tries the candidates in ranked order and skips one whose `render` returns nothing or throws (a throw fires the action `hyperpress_frontpage_countdown_error` with the candidate id and the `Throwable`). The choice is made per request, so a full-page cache keeps the chosen countdown until it expires: keep its lifetime shorter than the gaps between changes (a day ending, a lead window opening). `hyperpress_frontpage_now` is a test-only clock. `hyperpress-event` (`FrontpageCountdown`) is a source too: each upcoming event is a candidate from the lead time (Events settings page, default 21 days) before its start, until its end (no `fallback_after`).
- NextGEN icon styles: `hyperpress-media` (`NextGen\IconStyles`, registered unconditionally) dequeues NextGEN Gallery's two Font Awesome styles (`nextgen_gallery_icons`, `nextgen_gallery_icons_scope`) on the front end, on `wp_print_styles` (priority 100) and `wp_print_footer_scripts` (priority 5). The theme draws icons with Font Awesome's script, and NextGEN's `.fa-stack-2x { font-size: 2em }` doubles stacked icons. Nothing happens in wp-admin. A site that needs NextGEN's icons (for example NextGEN Pro) returns false from the `hyperpress_media_dequeue_nextgen_icons` filter. NextGEN's per-site setting `disable_fontawesome` is not needed while the plugin is active.
- Events: `hyperpress-event` registers the post type `hyper_event` at `/event/<slug>/` (no archive: the Events hub is a normal Page, usually `/events/`, holding `[hyperpress_event_list]`) and the taxonomy `hyper_event_series` at `/event/series/<term>/`. Deactivating the plugin unregisters the types and flushes the rules; the rewrite flush is keyed on the plugin version plus `Rewrite::RULES_REVISION` (bump it when routes change). The series edit screen warns when an event has the series slug (`Slugs::conflict_notice`). With plain permalinks menu items keep the series archive link. The evergreen alias `/event/<series-slug>/` answers a 302 to the series' current event (`Alias`, on `template_redirect` priority 0, ahead of NextGEN Gallery's early `redirect_canonical()` call). A single event renders full-screen (the plugin answers `hyperpress_single_full_screen`, so the theme drops the sidebar and keeps breadcrumbs) through its `content_template` file, and a new event is scaffolded with the countdown, tickets and photos shortcodes. Shortcodes: `[hyperpress_event_countdown]` (current event, or `id="123"`; nothing once the event is over), `[hyperpress_event_tickets]` and `[hyperpress_event_photos]` (always the current event, no `id`; attributes `title`, `subtitle`, `color`, `anchor`) and `[hyperpress_event_list]` (`series`, `show`, `limit`). The Events settings page (option `hyperpress_event`) has the keys `hyperpress_event_default_banner_color`, `hyperpress_event_fallback_subtitle`, `hyperpress_event_hub_page`, `hyperpress_event_frontpage`, `hyperpress_event_frontpage_lead_days` and `hyperpress_event_countdown_past_zero`. The plugin answers `hyperpress_frontpage_countdown_candidates`, `hyperpress_single_full_screen` and `hyperpress_banner_shortcode_default_color` (the event's colour inside `[hyperpress_banner]` on an event). It offers `hyperpress_event_now` (test-only clock), `hyperpress_event_woocommerce_active`, `hyperpress_event_nextgen_active` and `hyperpress_event_nextgen_template` (NextGEN legacy template file name in, file name or empty out). Tickets need WooCommerce and photos need NextGEN Gallery: without them the matching fields and sections are absent (`Integrations`). NextGEN output is delegated to `[ngg ...]` through `do_shortcode()`, never printed as text, and the `template` argument is added only when the parent theme has the file. Unit-suite rule: read the series term with `HyperPress\Utils\RequestTerm::get( $taxonomy )`, never `is_tax( 'x' )` with an argument or `get_queried_object()`.
- Labels: `hyperpress-label` owns the registry, the Labels settings page and the renderer. Season, program, competition (district, week, type) and sponsor register their own. Plugins register labels on the `hyperpress_label_register` action; theme templates call `do_action( 'hyperpress_labels' )`.

## Git

- Commit from the repo root with explicit pathspecs: `git add <paths>` then `git commit -m "..." -- <paths>`. Never a bare `git commit`.
- Commit style follows the root `../AGENTS.md` (`type(scope): lowercase summary`, e.g. `fix(shortcode): …`).
